# 実験コード規約

このディレクトリのコードは**保守しない前提**。目的は仮説の検証であって、保守可能なコードを書くことではない。速度を優先する。

ただし**破棄はしない。実験は成果物である**（ADR-003）。何を試して何が駄目だったかは記録として残す。「保守しない」は「消してよい」を意味しない。

本番コード規約（`.claude/rules/production-code.md`）とテスト規約は、ここには適用されない。

## 許容されること

以下は指摘・修正の対象としない。良いコードにしようとしないこと。

- 値のハードコーディング（パス、パラメータ、閾値、期間）
- アルゴリズムに渡す直前での変数の直接書き換え
- コピー&ペーストによる重複
- 型ヒントの省略
- 関数分割をせず手続き的に書くこと
- グローバル変数
- 使われなくなったコードのコメントアウト放置
- テストコードを書かないこと

**「ついでにリファクタリングしましょうか」と提案しない。** 実験コードの整理は価値を生まない。

## テストファーストは適用しない

仮説が固まっていない段階で期待値を先に書くことはできないため、テストファースト規約の対象外とする。

ただしテストの代わりに、以下のアサーションをコード中に置くこと。実験結果が静かに壊れることを防ぐ目的であり、テストの体裁は不要。

- 読み込み直後のデータ件数と列の存在
- 分割後の学習・評価データの件数と、重複がないこと
- 特徴量行列に欠損・無限大が残っていないこと
- 目的変数の正例件数
- 予測結果の件数が入力と一致すること

想定と違えば即座に停止させる。実験の失敗は早く気づくほど安い。

## 禁止されること

数は少ないが絶対に守る。すべて「実験結果が信用できなくなる」か「事故になる」ことに直結する。

### 1. 乱数シードの未固定
固定していない実験の結果は比較できない。Python標準・NumPy・使用フレームワークのすべてで固定する。

### 2. 実行条件の記録漏れ
実行時に以下を出力先へ必ず書き出す。**これが無い実験結果は本設計フェーズで再現できず、破棄される。**

- 乱数シード
- 入力データのパス・抽出条件・抽出日時
- コードのコミットハッシュ（未コミットなら差分も）
- **コード中に直接書き込んだ値**（ハードコードは許容するが、記録しないことは許容しない）
- 主要なハイパーパラメータ
- 実行日時と所要時間

### 3. データ分割前のfit
スケーリング、欠損補完、エンコーディング、次元削減など、データから統計量を学習する処理を分割前に実行しない。リーケージにより結果が無効になる。

### 4. 評価データの参照
最終評価用に分離したデータを、モデル選択・閾値調整・特徴量選択のために参照しない。参照した場合はその事実を記録し、当該データを最終評価に使わない。

### 5. 推論時に取得できない特徴量の使用
目的変数から派生した値、処理完了後にしか確定しない値、未来の情報を特徴量に含めない。判断がつかない場合は使用せず、ユーザーに確認する。

### 6. 生データ・認証情報のコミット
出力先が `.gitignore` 対象であることを確認してから書き出す。APIキーをコードに直書きしない。

### 7. `src/` からの参照
`experiments/` は `src/` を import してよいが、**`src/` から `experiments/` を import してはならない**。本番コードが実験コードに依存すると、実験の削除ができなくなる。

## ディレクトリ規約

**1つの実験は3箇所に分かれる。ディレクトリ名を完全に一致させること。**

```
experiments/EXP-NNN-{slug}/     実験コード（Git追跡）
  run.py                        実験スクリプト（構成は自由）
  config.md                     実行条件の記録（上記「2」の内容）

outputs/EXP-NNN-{slug}/         全出力（.gitignore対象）
                                指標・予測結果・図表・埋め込み・中間集計

docs/experiments/EXP-NNN-{slug}/  文書（Git追跡・公開可能なものに限る）
  plan.md                       実験計画書。実施前に書き、実施後に書き換えない
  report.md                     結果と考察
  figures/                      レポートに採用した図のみ
```

- **出力先は `experiments/` 配下ではなく、トップレベルの `outputs/` である**（ADR-002）。実験コードのディレクトリに `outputs/` を作らない
- 実験IDは `EXP-NNN` 形式の連番とし、再利用しない。**失敗した実験のディレクトリも削除しない**（同じ失敗を繰り返さないため）
- 実験は `exp/EXP-NNN-{slug}` ブランチで行い、`plan.md` と `report.md` が揃った時点でマージする（ADR-003）。**結果がNo-Goでもマージする**

### 出力の置き分け

**取得データは機密扱い**（`CLAUDE.md` 3章）。境界は「生の発言と話者を出さない」。

| 置き場所 | 内容 | Git |
|---|---|---|
| `outputs/EXP-NNN-{slug}/` | 全出力。個票を含んでよい | 対象外 |
| `docs/experiments/EXP-NNN-{slug}/figures/` | レポートに採用した図のみ | 追跡 |

**図に発言本文を焼き込まない。** ラベルには特徴語・クラスタIDを使う。
目視確認のために個票を抜き出す場合は `private/` へ置く。

## ログ

`print()` ではなく `logging` を使う。バックグラウンド実行でログが消えるため、ここだけは実験でも守る。

## 検証の依頼（ADR-008）

**結果が出たら `experiment-analyst` エージェントに検証を依頼する。自分で「良い結果が出た」と結論づけない。**

依頼するのは実験の終了時だけではない。**多段の実験では、不可逆な決定を含むステージの直後にも検証を挟む。**

### なぜ終了時だけでは足りないか

段階的に決めていく実験では、**先行するステージの決定が後続ステージの比較の前提になる。** 前提が誤っていても、後続は「その前提の下でどちらが良いか」を比較するだけなので、**誤りは矛盾として表面化しない。** 検出の機会は決定の直後にしかない。

撤退基準（D-N）やチェックポイント（CP-N）はこれを防がない。**あれらは「無駄に走り続けること」を止めるものであって、「誤った前提のまま走り続けること」は止めない。**

### レビューポイント（RP）の置き方

**実験計画の作成時に、以下を満たす位置へ RP を置く。**

| 原則 | 内容 |
|---|---|
| 1 | **不可逆な決定を含むステージの直後**に置く。決定を伴わないステージには置かない |
| 2 | **最も重いステージの手前**に置く。手戻りのコストは決定の位置で決まる |
| 3 | **主観評価によって選択を確定するステージの直後**には必ず置く。自分の主観評価を自分で採否判断すると独立性が確保できない |
| 4 | **各 RP で問う内容を、実験の実施前に固定する。** 固定していない観点をその場で追加しない |
| 5 | **RP を通過するまで次のステージへ進まない** |

**全ステージに置かない。** レビューが結論の追認になり、儀式化して本当に見るべき箇所での緊張が失われる。**回数ではなく位置が重要である。**

### 置き場所

**`plan.md` は実施後に書き換えない**（`.claude/rules/documentation.md` 5節）。実験の開始後に RP を追加する場合は `plan.md` を触らず、**設計書の改訂**として反映する（`ISSUE-NNN` または `ADR-NNN` の起票を先行させる）。

### 記録

**RP の通過率と、レビューによって実際に変更された判断の件数を `report.md` に記録する。** 差し戻しが一度も出ないのであれば、レビューが機能していないか不要であったかのいずれかであり、その判断材料となる（[ADR-008](../../docs/decisions/ADR-008-review-checkpoints-in-large-experiments.md) 7節）。
