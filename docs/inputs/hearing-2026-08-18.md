## 1. 目的・手法の方向性

**【発言】** 単なる頻出語分析ではなく、「国会で何が論点になっているのか」を教師なし学習で抽出して、その盛衰を時系列で追うアプリ。

**【発言】** データを収集 → Embedding または TF-IDF → クラスタリング → クラスタを LLM で命名し、どんな話題があったのかを可視化。これを PoC として実施する。

**【発言】** 2020〜2026年の発言を収集するのが要件だが、まずは1年分（2025年）で何が議論されていたかを PoC するのがよい。

→ 要件定義書 1.2節・1.3節・2.1節・2.4節の根拠。

## 2. 想定利用者・アウトプット

**【発言】** 想定利用者は個人。

**【発言】** リポジトリ自体を教育目的で紹介する可能性はある。

**【発言】**（後の補足）教育目的というのは社員教育に近いものであって、それを主目的にする必要はない。実務を想定して作ったものを、教育展開が必要になったらこちらで料理して説明する方針なので、忘れてよい。

→ **教育目的は要件外**（要件定義書 3.2節）。一度スコープに含める方向で検討されたが、依頼者の指示により除外した。

**【発言】** 今のところ可視化ダッシュボード予定。

→ 要件定義書 1.3節・8章の根拠。

## 3. PoC の進め方（撤退基準）

**【発言】** これに関しては研究的な要素が強く、初回の PoC はまずやってみて、それをベンチマークにするのが現実的。それ以降はある程度ベンチマークができる。

**【承認】** 上記を規約（実験計画書に撤退基準を書き、後で緩めない）と両立させるため、担当が「EXP-001 を探索的実験と位置づけ、**撤退基準は品質ではなく成立性で置く**（収集完了・計算完走・クラスタ非退化）。品質は測定のみで閾値を置かずベンチマーク化する」案を提示。

**【発言】** 撤退基準は成立性でよい。

→ 要件定義書 3.3節の根拠。

## 4. 未確定事項への回答

### Q-001: 分析結果と意思決定の接続

**【判断】** (b) 個人的な知的探求・リサーチ目的で足り、明示的な行動変化は想定しない。

→ 要件定義書 1.4節。ビジネス指標による評価を行わないことの根拠。

### Q-002: 記述的分析か予測か

**【判断】** (a) 記述的分析のみ。将来予測・早期検知はスコープ外。

→ 要件定義書 2.3節。

### Q-004: Phase 2 への移行判断基準

**【発言】** 意思決定が難しい。こういったクラスタリングは主観と定量的数値が一致しないことがしばしばある。複数手法を試して、定量指標で比較して決めるのか、主観的に決めるのかも含めて、実験して決めることになる。

→ 要件定義書 3.3.1節。**「定量指標と主観評価の一致度」を測定項目に加える設計は担当の提案**だが、その前提となる「主観と定量が一致しないことがしばしばある」という認識は依頼者の発言。

### Q-007a: 可視化の技術スタック

**【発言】** Streamlit を使ったことがない。Jupyter で可視化していたが、メリットが大きいのであれば Web アプリでもよい。TensorBoard のようなものをイメージしておけばよいか。

**【承認】** 担当が「ダッシュボードは Streamlit、実験時の可視化は Jupyter。探索と成果物提示で役割を分ける」案を提示。

**【発言】** それで大丈夫。

→ 要件定義書 8章・8.2節。

### Q-008: 本番運用時の更新頻度

**【判断】** (a) とりあえずは手動で随時実行。

→ 要件定義書 10章。「とりあえず」という留保つきの回答であり、Phase 2 で再検討の余地がある。

### Q-009: 本番対象期間

**【発言】** コロナ前後という比較もできるので、2019〜2025年というのがよいかもしれない。正直、年数は適当に考えた。2026年は全部揃っていないので外してもよい気がした。

→ 要件定義書 5.6節、[ADR-001](../decisions/ADR-001-poc-data-layer.md) 9章。**当初の「2020〜2026年」に明確な根拠はなかった**ことが本発言で判明した。

### Q-010: 参照論点リストの作成方法

**【発言】** 客観的な指標から選びたいが、何かよい案はあるか。

**【承認】** 担当が候補（A: 施政方針演説・所信表明演説の項目／B: 提出議案リスト／C: NDL調査資料／D: 報道の年間回顧）を提示し、A を主軸・B を補完とする案を推奨。

**【発言】** A と B どちらも PoC で使ってみるのがよい。ここも PoC の論点でよい。

→ 要件定義書 5.2.1節。**参照A・Bという具体的な情報源は担当の提案であり、依頼者の発言に含まれていたわけではない。** 依頼者が述べたのは「客観的な指標から選びたい」という方針と、提示された2案を両方採用するという判断。

### Q-011: 現行の論点把握手段

**【判断】** (b) 特に体系立った方法はない。

→ 要件定義書 7.1節・7.1.1節。現行手法との性能比較が成立しないことの根拠。

## 5. LLM のコストとモデル選定

**【発言】** LLM のコスト見積もりが必要になる。今のところ Gemini を想定しているが、モデルの選定、コストも含め検討になる。これも PoC のスコープ。

**【発言】** コストを比較して現実的なモデルを決めることになる。コストが現実的でない場合は TF-IDF なども検討になる。

→ 要件定義書 9章 NFR-005、Q-013（新設）の根拠。

## 6. ベクトル化方式

**【発言】** ローカル埋め込みモデル（Sentence-Transformer）のようなものでもコストによっては可能。**キーワードが支配的な場合、意外と Embedding より古典的な TF-IDF が勝る印象もある。**

→ 要件定義書 2.4節。**TF-IDF を「コストの退避先」ではなく「品質面でも対等な第一候補」として位置づける根拠。** 担当は当初 TF-IDF を退避先として提示していたが、本発言により位置づけを改めた。

### Q-012: 後方視点のクラスタ定義の扱い（2026-08-18）

担当が「全期間を一括でクラスタリングすると、2019年の発言が2025年までのデータで定義されたクラスタに割り当てられ、当時存在しなかった論点区分で過去を解釈することになる」と説明し、(a) 全期間一括で許容する／(b) 期間分割で学習しクラスタの対応付けを別途設計する、の2案を提示。担当は実装コストを理由に (a) を推奨した。

**【判断】** 設計次第だが、いったん (b) 期間分割で学習しクラスタの対応付け（トピックの同一性判定）を別途設計する。**ただし、ここは設計で見直すでよい。**

→ 担当の推奨（a）とは異なる選択である。**「設計で見直す」という留保が明示されている**点に注意すること。
