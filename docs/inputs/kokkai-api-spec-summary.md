## この API について知っておくべき前提

**公式ページ以外に情報源が存在しない。** SDK、スキーマ定義ファイル、版管理された仕様書、変更履歴、GitHubリポジトリのいずれもない。

この結果、**仕様変更を事前に検知する手段がない。** 予告なく変更されても、こちらから気づく方法は次の2つに限られる。

1. レスポンスのスキーマ検証で異常を捕捉する（`pydantic`。`.claude/rules/production-code.md` 3章で必須）
2. 実行時のエラーとして顕在化する

**変更を検知した場合は `ISSUE-NNN`（種別: 外部要因）として起票する**（`.claude/rules/documentation.md` 6節）。

## エンドポイント

いずれも HTTP GET。`https://kokkai.ndl.go.jp/api/{endpoint}?{検索条件}`

| エンドポイント | 返戻内容 | `maximumRecords` 範囲 | 既定値 |
|---|---|---|---|
| `meeting_list` | 会議録のメタ情報のみ（**本文を含まない**） | 1〜100 | 30 |
| `meeting` | 会議録のメタ情報＋**当該会議録の全発言本文** | 1〜10 | 3 |
| `speech` | **ヒットした発言の本文**＋所属する会議録の情報 | 1〜100 | 30 |

本プロジェクトは発言単位を分析単位とするため `speech` を用いる（要件定義書 2.3節）。

ソート順は**会議開催日の新しい順**。ページングはレスポンスの `nextRecordPosition` を辿る。

## 検索パラメータ

| 区分 | パラメータ | 備考 |
|---|---|---|
| 出力制御 | `startRecord` / `maximumRecords` / `recordPacking` | `recordPacking` は `xml`（既定）または `json` |
| 院・会議 | `nameOfHouse` / `nameOfMeeting` | 院名は「衆議院」「参議院」「両院」「両院協議会」。会議名は部分一致 |
| 検索語 | `any` | 発言内容。部分一致 |
| 発言者 | `speaker` / `speakerPosition` / `speakerGroup` / `speakerRole` | 役割は「証人」「参考人」「公述人」 |
| 日付 | `from` / `until` | `YYYY-MM-DD` |
| 回次・号数 | `sessionFrom` / `sessionTo` / `issueFrom` / `issueTo` | |
| 識別子 | `speechID` / `issueID` | 完全一致 |
| 絞り込み | `speechNumber` / `supplementAndAppendix` / `contentsAndIndex` / `searchRange` / `closing` | `searchRange` は「冒頭」「本文」「冒頭・本文」 |

### 区切り文字の論理が параметрによって異なる

**この非対称性は取り違えやすい。**

| パラメータ | 半角スペース区切りの意味 |
|---|---|
| `any`（検索語） | **AND** |
| `nameOfMeeting`（会議名） | **OR** |
| `speaker`（発言者名） | **OR** |

その他の制約: 検索条件は全体で2,000バイトが上限。**検索条件を1つも指定しないとエラー**（19007）。

## 負荷に関する制約

公式ページの記載は次のとおり。

- 「システムの運用に影響のあるような負荷のかかる利用（短時間での大量アクセス等）はご遠慮ください」
- 「機械的なアクセスを行う場合、**多重リクエストは避けてください**。また、**データを取得し終えてから数秒程度空けて**次のリクエストを行うようにしてください」
- 「安定運用に支障をきたすと当館が判断した場合には、**予告なくアクセスを遮断する等の措置**をとることがあります」

`CLAUDE.md` 0章の「逐次アクセスのみ・並列化禁止」はこの記載に基づく。

## エラーコード

| コード | 内容 | リトライ |
|---|---|---|
| 19001 | 混雑。しばらくしてから再アクセス | **可**（唯一のリトライ対象） |
| 19004 | `startRecord` が範囲外 | 不可 |
| 19005 | `maximumRecords` が 1〜100 の範囲外 | 不可 |
| 19006 | `maximumRecords` が 1〜10 の範囲外 | 不可 |
| 19007 | 検索条件が未指定 | 不可 |
| 19011 | 検索条件の入力に誤り | 不可 |
| 19012 / 19013 | `from` / `until` の日付書式が不正 | 不可 |
| 19014 | `from` > `until` | 不可 |
| 19018 / 19019 | `from` / `until` が存在しない日付 | 不可 |
| 19020 | 入力可能文字数の超過 | 不可 |

**19001 以外はリトライしても解決しない**（条件の誤りであるため）。`CLAUDE.md` 0章の規定に対応する。
上表以外のエラーが出た場合は、公式ページの問い合わせ先へ連絡することが求められている。

## 著作権・利用条件

- 国立国会図書館職員の発言および**データベース自体**の著作権は同館に帰属
- **その他の発言の著作権は個々の発言者に帰属**し、利用には原則として著作権者の許諾が必要
- ただし著作権法の権利制限規定が適用される場合は許諾不要。**「電子計算機による情報解析」**、私的使用のための複製、引用、政治上の演説または陳述に該当する箇所の利用、報道が例示されている
- 許諾の要否および利用条件の確認は**利用者の責任**とされ、同館は責任を負わない

本プロジェクトが取得データを機密扱いとし、発言本文を Git 追跡対象へ書き込まない方針は、この帰属関係に基づく（[ADR-002](../decisions/ADR-002-public-private-boundary.md)）。

## この仕様書から分からないこと

**公式ページはパラメータと書式を定めるが、実際の挙動は記載していない。** 以下は実際にアクセスして測る以外に知る方法がない。

| 項目 | なぜ重要か |
|---|---|
| 1リクエストの実応答時間 | 収集の所要時間を左右する（PoC設計書 2.2節 D-1） |
| 19001（混雑）の発生頻度と時間帯依存 | リトライ設計と総所要時間に影響する |
| `maximumRecords` を上限まで指定した場合の安定性 | 上限が使えるかで所要時間が桁で変わる |
| 発言本文の文字数分布 | トークン数・コスト見積もりの基礎（同 8.4節） |
| 短文発言（「異議なし」等）の割合 | 前処理の除外閾値に直結（同 Q-003） |
| 会議種別によるフォーマットの差異 | 前処理の設計に影響する |
| `nextRecordPosition` の挙動（欠番・重複の有無） | 収集の冪等性に影響する |

**したがって収集は準備作業ではなく、最初の実験である。** PoC設計書は収集を S-1 として実験ステージに位置づけ、H-001（収集の成立性）を最優先の検証仮説としている。上記の項目は収集時に実測し、`config.md` および実験レポートへ記録すること。
