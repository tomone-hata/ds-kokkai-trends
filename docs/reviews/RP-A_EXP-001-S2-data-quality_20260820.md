# RP-A 検証レポート: EXP-001 S-2 データ品質確認

| 項目 | 内容 |
|---|---|
| 対象 | EXP-001 S-2（データ品質確認） |
| 実施日 | 2026-08-20 |
| 検証者 | `experiment-analyst` |
| 問い（設計書 2.4節で固定） | データが分析に足るか。文字数分布・短文割合の解釈が、S-4 の除外閾値の根拠として妥当か |
| 判定 | **差し戻し** |

## 判定理由

S-2 は**生の `speech` 列の文字数**を測っているが、設計書 6.1節の処理順序により、除外閾値が適用されるのは**正規化（3-1〜3-3）後の本文長**である。`speech` は冒頭に話者表記を含み、その長さは実測で平均 8.79字・中央値 8字である。この系統差により「短文が大量に存在するという想定は成立しなかった」という解釈は反転する（正規化後の近似では10字以下が 12件 → 3,185件）。

加えて Q-4 の集計が設計書 6.3.1節の指定と3点で異なる（ビン幅・ビン境界・重複率の定義）。設計書の定義を字義どおり適用すると **50% を超えるビンが1本も存在せず T1 が未定義**になり、実装の定義では T1=20 になる。**測り方によって T1 が「未定義 / 10 / 20」に割れる**ため、現状の S-2 は S-4 の除外閾値の根拠として使用できない。

再集計は1日未満で済み、ここで止める手戻りは S-3（1.5日）・S-4（1日）より小さい。

## (b) 集計の正しさの検証結果

### 問題なしと判定した項目

| 観点 | 判定 | 根拠 |
|---|---|---|
| Q-4 のビン割り当て構造（`speech` でグループ化した後にビンを割り当てる） | **問題なし** | 完全一致の重複群は文字列が同一であるため文字数も同一であり、1つの群が複数ビンにまたがることはない。分母（`SUM(c)`）もビン内の全レコードを数えており、取りこぼしはない。**構造そのものは正しい** |
| `LENGTH()` の意味 | 問題なし | DuckDB の `LENGTH()` は VARCHAR に対して文字数を返す（バイト数ではない）。全角前提の日本語テキストで意図どおり |
| Q-3 の分位点算出 | 問題なし | `QUANTILE_CONT` は補間するため p99 = 2,220.4 のように非整数になるが、閾値候補の走査は `WHERE LENGTH(speech) <= t` の直接カウントであり、分位点の補間は閾値決定に影響しない |
| Q-1 の総件数・重複 | 問題なし | 118,566件・`speechID` 重複0。アサーションで担保されている。再集計でも一致 |
| Q-5 の欠損判定 | 問題なし | NULL と空文字を分けて数えており、`speakerGroup` と `speakerYomi` の欠損が完全に同一行（25,166件）である指摘は再現した |
| ビン別件数の合計 | 問題なし | Q-4 の9ビンの合計は 118,566 で総件数と一致する |

### 問題ありと判定した項目

#### B-1. ビン境界が1ずれており、`config.md` の表のラベルが実際の集計と一致しない

実装のビン割り当ては `(SELECT MAX(b) FROM UNNEST([0,10,20,50,100,200,500,1000,2000]) WHERE b <= len)` である。したがって実際の区間は下表の右列になる。

| `config.md` の表記 | 実際に集計された区間（実測で確認） | 件数 |
|---|---|---|
| 1〜10 | **1〜9** | 8 |
| 11〜20 | **10〜19** | 3,288 |
| 21〜50 | **20〜49** | 7,561 |
| 51〜100 | **50〜99** | 11,322 |
| 101〜200 | **100〜199** | 17,623 |
| 201〜500 | **200〜499** | 46,074 |

**検算で矛盾が出る。** `config.md` は Q-3 で「10文字以下 = 12件」、Q-4 で「1〜10 = 8件」と記載しており、両立しない。差の4件は `len = 10` が次のビンへ入っているために生じる。同様に、真に 11〜20 の区間の件数は 3,495件であり 3,288件ではない。

**これは表記の誤りにとどまらない。** 設計書 6.3.1節 手順3・4 は「ビンの**上端**を T1 / T2 とする」と定めており、境界が1ずれれば導かれる閾値も1ずれる。

#### B-2. ビンの解像度が設計書の指定より粗く、手順3が適用できない

設計書 6.3.1節 手順1 は **1〜10, 11〜20, 21〜30, …, 91〜100, 101〜200, 201〜**（10字刻み10本＋2本）を指定している。実装の `LENGTH_BINS = [0,10,20,50,100,200,500,1000,2000]` は **21〜100 を2本（20〜49, 50〜99）にまとめており、21〜30 から 91〜100 までの8本が算出されていない。**

手順3は「重複率が 50% を超える**最大のビン**の上端を T1 とする」である。**粗いビンでは「最大のビン」を特定する解像度がない。**

**そしてこの粗さは実際に構造を隠している。** 設計書どおりの10字刻みで再集計すると、**51〜60 の帯に非単調な突出**が現れる。

| 区間（生の文字数） | 件数 | 異なり本文 | 重複群に属する割合 | 1 − ユニーク÷件数 |
|---|---|---|---|---|
| 41〜50 | 2,250 | 1,940 | 18.44% | 13.78% |
| **51〜60** | **3,142** | **2,110** | **38.83%** | **32.85%** |
| 61〜70 | 2,208 | 1,966 | 14.49% | 10.96% |

51〜60 の重複率は隣接ビンの2倍以上であり、粗ビン（50〜99）の 19.10% では見えない。**今回は 50% に届かなかったため T1 は変わらないが、「重複率は文字数に対して単調減少する」という暗黙の前提が成り立たないことを示している。** 手順3は最大のビンを探す規則であり、単調性が崩れる以上、指定された解像度で算出しなければ規則の適用を保証できない。

#### B-3. 重複率の定義が設計書と異なり、その差が判定閾値 50% を跨ぐ

| 出典 | 定義 |
|---|---|
| 設計書 6.3.1節 手順2 | 重複率 = **1 − ユニーク発言数 ÷ ビン内発言数** |
| `run_02_quality.py`（実装） | `SUM(CASE WHEN c > 1 THEN c ELSE 0 END) / SUM(c)` = **重複群に属する発言の割合** |

**両者は別の量である。** 設計書どおりのビン（生の文字数、11〜20）で実測すると次のようになる。

| 定義 | 値 | 50% 判定 |
|---|---|---|
| 設計書 6.3.1節 手順2 の式 | **49.67%**（1 − 1,759 ÷ 3,495） | **超えない** |
| 実装の式 | **64.95%**（2,270 ÷ 3,495） | 超える |

**設計書の定義を字義どおり適用すると、50% を超えるビンが1本も存在しない。** すなわち手順3で T1 が定まらず、E-1・E-2 が構成できず、**S-4 の比較設計そのものが成立しない。**

**どちらの定義を採るかを、結果を見た後に選ぶことはできない。** 50% を挟んで結論が反対に出る帯が実在する以上、事後に選べば「結果に合わせて基準を選んだ」ことになる（`.claude/rules/documentation.md` 5節「撤退基準を実施後に緩めない」と同じ思想）。

## (c) 文字数分布・短文割合の解釈の妥当性

### C-1. 測っている量が、閾値を適用する量と異なる（最も重い指摘）

設計書 6.1節は処理順序を固定している。**工程3（テキスト正規化）→ 工程4（短文発言の除外）**である。したがって除外閾値が比較される文字数は、**正規化後の本文長**でなければならない。

S-2 は生の `speech` 列に対して `LENGTH(speech)` を測っている。この列は**冒頭に話者表記を含む**（設計書 6.2節 3-3 が除去対象として明記しているもの）。

| 実測項目 | 値 |
|---|---|
| `○` で始まる発言 | **117,440件（99.05%）** |
| 冒頭の話者表記の長さ（`○` から最初の全角空白まで）の平均 | **8.79字** |
| 同 中央値 | **8字** |
| 同 90パーセンタイル | **13字** |
| 同 最大 | **21字** |
| 3-2（連続空白の圧縮・前後空白除去）だけで減る文字数の平均 | **12.31字**（中央値 4字） |

**S-2 の文字数分布は、閾値が実際に適用される量より系統的に長い側へずれている。** そのずれの大きさ（中央値で8字）は、議論している閾値の水準（10〜30字）と同じ桁である。

### C-2. この系統差により、S-1 の結論が反転する

`config.md` S-1 節は次のように結論している。

> 「10文字以下は12件しかない。『異議なし』等の定型的な短文が大量に存在するという想定は成立しなかった。」
> 「5文字以下は1件も存在しない。」（S-2 節 Q-3）

**この2つはいずれも測り方の産物である。** 話者表記を除いた近似で測り直すと次のようになる。

| 閾値 | 生の文字数での件数 | 正規化後（近似）での件数 | 差 |
|---|---|---|---|
| ≤ 5字 | **0**（0.00%） | **189**（0.16%） | +189 |
| ≤ 10字 | **12**（0.01%） | **3,185**（2.69%） | **+3,173** |
| ≤ 15字 | 770（0.65%） | 4,454（3.76%） | +3,684 |
| ≤ 20字 | 3,507（2.96%） | 5,508（4.65%） | +2,001 |
| ≤ 30字 | 5,865（4.95%） | 8,361（7.05%） | +2,496 |
| ≤ 50字 | 11,165（9.42%） | 13,894（11.72%） | +2,729 |

正規化後の最小文字数は **3字**である。

**「5文字以下が0件」は現象ではなく、全レコードに 8〜9字の接頭辞が付いていたことの帰結にすぎない。** 平均 8.79字の話者表記が付くため、4字程度の定型発言は生の文字数で 13字前後に押し上げられ、11〜20 の帯に移る。**これが 11〜20 帯の重複率が突出する理由である。**

### C-3. 定型短文の塊は実際に存在する

正規化後（近似）の 1〜10字帯を再集計した。

| 項目 | 値 |
|---|---|
| 件数 | **3,185** |
| 異なり本文 | **795** |
| 重複群に属する割合 | **86.94%** |
| 1 − ユニーク ÷ 件数 | **75.04%** |
| 最大反復回数 | **148** |

**この帯は 795種類の本文が 3,185回出現している。** 設計書 6.3A.6節が挙げる「会議の開会・閉会の宣告、議事進行、点呼」等の定型発言が想定どおり存在することを示す。**「想定は成立しなかった」という記録は訂正を要する。**

### C-4. Q-4 の完全一致重複は、定型発言を系統的に過小検出している

Q-4 の目的は設計書 3.3節で「定型発言の検出」と定義されている。しかし話者表記を含んだまま完全一致を取るため、**同一の定型文言でも発言者が異なれば別の本文として数えられる。**

| 指標 | 生の `speech`（S-2 の値） | 正規化後（近似） |
|---|---|---|
| 異なり本文 | 113,819 | **111,360** |
| 重複群に属する発言 | 6,356（**5.36%**） | **8,678（7.32%）** |
| 最大反復回数 | **142** | **417** |

**最大反復回数が 142 から 417 へ、3倍近くになる。** 目的（定型発言の検出）に対して測定量が合っていない。

### C-5. 文字数分布の上位側に、発言ではないレコードが混入している

`speechOrder = 0` のレコードが **1,126件**存在する。これは会議数（`issueID` のユニーク数）**1,126** と完全に一致し、1会議あたり厳密に1件である。`○` で始まらないレコードはこの 1,126件のみで、`speaker` 列の文字数は全件5字で一定である。

| 項目 | 値 |
|---|---|
| 件数 | 1,126（全体の 0.95%） |
| 平均文字数 | **1,733.2** |
| 中央値 | 1,496 |
| **最大** | **46,976** |
| 総文字数に占める割合 | **3.96%**（1,951,554 / 49,299,337） |

**`config.md` が Q-3・Q-7 で「最大 46,976」と記録している値は、発言ではなくこのレコードである。** 10,000字以上のレコード13件のうち4件がこれに該当し、その平均は 23,304字である。

これを除いた場合、発言側の分布は次のようになる。

| 統計量 | S-2 の記録（全118,566件） | `speechOrder = 0` を除く（117,440件） |
|---|---|---|
| 平均 | 415.8 | **403.2** |
| 中央値 | 318.0 | 314.0 |
| p99 | 2,220.4 | **2,020.6** |
| 最大 | 46,976 | **16,547** |

**このレコードは短文除外（下限）では除去できない。** 別の規則が要る。設計書 6.4節が測定項目として挙げる「(a) 文字数の分布と上位側の裾の重さ」「(c) 最長級の発言10件の目視確認」は、現状のままだと会議録の冒頭情報を対象にすることになる。

## (d) S-4 の除外閾値の根拠として足りるか

### D-1. 測り方によって T1 が3通りに割れる

設計書 12.1節 U-6 は「短文除外の閾値 T1・T2 は、**S-2 の文字数分布と重複率の実測により、6.3.1節の手順で機械的に決まる**」としている。**現状の S-2 では機械的に決まらない。**

| 測る対象 | 重複率の定義 | 50% を超える最大のビン | 帰結する T1 / T2 |
|---|---|---|---|
| 生の文字数 | 設計書 6.3.1節 手順2 の式 | **なし**（11〜20 が 49.67%） | **未定義**（S-4 が実行不能） |
| 生の文字数 | 実装の式 | 11〜20（64.95%） | **20 / 30** |
| 正規化後（近似） | 設計書 6.3.1節 手順2 の式 | 1〜10（**75.04%**） | **10 / 20** |
| 正規化後（近似） | 実装の式 | 1〜10（**86.94%**） | **10 / 20** |

**注目すべきは、正規化後に測ると2つの定義が同じ答え（T1 = 10）に収束することである。** 生のまま測ると定義の選び方で答えが割れるが、正規化後は割れない。**決定の頑健性という観点からも、測り直しは正規化後に行うべきである。**

> 上表は T1 を決めるためのものではない（それは S-4 の作業である）。**同じ手順が測り方次第で異なる出力を出す**という事実を示すために掲げている。

### D-2. 件数が近いことは、同じ集合を除外することを意味しない

「生で ≤20字」（3,507件）と「正規化後で ≤10字」（3,185件）は件数が近いが、集合は一致しない。

| 区分 | 件数 |
|---|---|
| 両方に該当 | **2,958** |
| 生 ≤20字 のみ | **549** |
| 正規化後 ≤10字 のみ | **227** |

**776件が入れ替わる。** 件数の近さを根拠に「どちらでも同じ」と判断してはならない。

### D-3. セグメント別の除外率が算出されていない

S-4 の決定規則（6.3.2節）は SE-A の解釈可能率と**除外件数の総数**しか見ない。したがって、**特定のセグメントを集中的に削り落とす閾値であっても、規則は検出しない。** 本プロジェクトの目的が時系列可視化である以上（要件定義書 1.3節）、この偏りは決定前に見えている必要がある。再集計した結果は次のとおり。

**院別（正規化後・近似、≤20字の割合）**

| 院 | 件数 | ≤20字 |
|---|---|---|
| 衆議院 | 67,140 | **5.89%** |
| 参議院 | 51,266 | **3.02%** |
| 両院 | 160 | 1.88% |

衆議院は参議院の約2倍である。

**会議種別（正規化後・近似）**

| 種別 | 件数 | ≤10字 | ≤20字 | ≤30字 |
|---|---|---|---|---|
| 委員会 | 113,496 | 2.61% | 4.53% | 6.74% |
| 本会議 | 2,928 | 0.14% | **1.09%** | **9.97%** |
| 調査会 | 1,117 | 5.73% | 10.74% | 16.29% |
| その他 | 1,025 | **14.63%** | **20.88%** | 23.12% |

**本会議は 20字と 30字の間で除外率が9倍に跳ねる。** 閾値の1段の違いが種別によって全く異なる効き方をする。

**月別（正規化後・近似、≤20字の割合）**

| 月 | 件数 | ≤20字 |
|---|---|---|
| 1月 | 1,001 | 4.40% |
| 2月 | 13,165 | 5.36% |
| 3月 | 20,713 | 4.47% |
| 4月 | 26,344 | 4.50% |
| 5月 | 23,918 | 4.18% |
| 6月 | 11,887 | 4.60% |
| 8月 | 972 | 3.19% |
| 9月 | 247 | 4.45% |
| 10月 | 356 | **2.25%** |
| 11月 | 11,341 | **5.71%** |
| 12月 | 8,622 | 4.70% |

月差は 2.25〜5.71% であり、除外が月次の件数推移へ一様には効かない。

### D-4. `config.md` の「その他」は内容的なノイズではない

Q-7 の「その他」1,025件の内訳は **憲法審査会 994件・情報監視審査会 31件**である。「その他」という区分名から非実質的な会議と読めてしまうが、**論点抽出の対象として実質を持つ会議種別である。** この区分は最も短文率が高い（≤20字で 20.88%）ため、閾値の設定によっては実質的な会議種別が集中的に削られる。**種別名を明示せずに「その他」のまま S-4 の材料にすると、判断を誤る。**
