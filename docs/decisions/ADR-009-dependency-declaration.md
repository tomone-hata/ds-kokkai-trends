# ADR-009: 依存は `pyproject.toml` に完全固定で宣言し、実験専用の依存を本番依存から分離する

## 1. 背景

### 現行規約と現状

`CLAUDE.md` 6章は「依存追加: `uv add {package}`」と定めている。この方法で構築した結果、`pyproject.toml` は次の形になっている。

```toml
dependencies = [
    "duckdb>=1.5.5",
    "httpx>=0.28.1",
    ...
]
```

**`uv add` は実行時点の最新版を解決し、下限（`>=`）として書き込む。**

`uv.lock`（355行・21パッケージ）は Git 追跡されており、**推移的依存を含む全バージョンが固定されている。** したがって `uv sync` で同一環境は再現できる。

### それでも残る2つの問題

**1. 宣言と実体が乖離している。** `pyproject.toml` には `>=1.5.5` と書かれているが、実際に使っているのはロックが指す版である。**人が読むファイルに、実際に使った版が書かれていない。**

**2. ロックを失うと同じ版に戻れない。** `uv lock --upgrade` の実行、ロックの競合解決、リポジトリの部分的な複製などでロックが更新・欠落した場合、`>=` の宣言だけでは元の版を復元できない。

### 分析結果の再現性に直結する

**本件は開発環境の利便性の問題ではない。**

`.claude/rules/experiment-code.md` 禁止事項1 は乱数シードの固定を求め、禁止事項2 は実行条件の記録を求めている。**いずれも「同じ入力から同じ結果が出ること」を担保するための規定である。**

**形態素解析の辞書はこの担保の外にある。** `sudachidict-core` のバージョンが変われば分かち書きの結果が変わり、語彙・TF-IDF・クラスタリング結果が変わる。**乱数シードを固定しても再現できない。**

EXP-001 は S-3 で SudachiPy による分かち書き（W-1・W-2）を文字 N-gram（W-3・W-4）と比較し、その結果を後続の全ステージが前提とする。**辞書バージョンが動けば、S-3 の決定そのものが再現できなくなる。**

### 実験専用の依存という論点

PoC は**採用する手法を決めるために複数の候補を比較する。** 比較して落選した手法のライブラリは、本番実装では不要になる。

**すべてを `dependencies` に入れると、本番の依存に落選した候補が残る。**

これは `.claude/rules/experiment-code.md` 禁止事項7（**`src/` から `experiments/` を import してはならない**）と同じ問題である。同節は「本番コードが実験コードに依存すると、実験の削除ができなくなる」と述べている。**依存パッケージについても同じことが起きる。**

## 2. 決定

**1. 直接依存は `pyproject.toml` に完全固定（`==`）で宣言する。`uv add` を使わず、`pyproject.toml` を直接編集し `uv sync --frozen` で導入する。**

**2. 実験でのみ用いる依存は `[dependency-groups]` の `exp` グループに分離する。本番実装での採用が確定した時点で `dependencies` へ移す。**

## 3. 検討した選択肢

| 案 | 内容 | 採否 |
|---|---|---|
| A | **`==` で完全固定し、`uv sync --frozen` で導入する。実験専用は `exp` グループへ分離** | **採用** |
| B | 現行どおり `uv add`（`>=`）とし、`uv.lock` を再現性の根拠とする | 不採用 |
| C | `pyproject.toml` に推移的依存まで含めて全パッケージを `==` で書く | 不採用 |
| D | 実験専用の依存を分離せず、すべて `dependencies` に入れる | 不採用 |

## 4. 判断根拠

1. **宣言が実体と一致する。** `pyproject.toml` を読めば、実際に使っている版がわかる。`uv.lock` は機械可読の全量記録であり、人が読む宣言とは役割が異なる。**両方を持つことに意味がある。**

2. **`uv add` は暗黙にロックを更新する。** 1つ追加するだけのつもりでも、解決の過程で他のパッケージの版が動きうる。**明示的に編集して `--frozen` で同期すれば、意図しない更新が起きない。**

3. **`--frozen` はロックの再解決を禁止する。** `uv sync --frozen` は「`uv.lock` を更新せずに同期する」（`uv 0.11.2` のヘルプ）。**ロックと環境の一致が保証される。**

4. **辞書・モデルのバージョンは乱数シードで担保できない。** 形態素解析辞書、事前学習済みモデルは、版が変われば出力が変わる。**実験の再現性の前提であり、`>=` で宣言してよいものではない。**

5. **実験専用の依存を分離すれば、本番実装への持ち込みを防げる。** PoC で比較する候補のうち採用されるのは一部である。**採用が確定したものだけを `dependencies` へ移すことで、移動そのものが決定の記録になる。**

## 5. 採用しなかった案を退けた理由

### 案B（現行どおり `uv add`）

**`uv.lock` があれば再現できるのは事実である。** 本ADRはロックの有効性を否定しない。

**しかし宣言と実体の乖離は残る。** `pyproject.toml` に `>=1.5.5` とだけ書かれた状態で、「この実験は duckdb のどの版で行われたか」を答えるには `uv.lock` を読む必要がある。**実行条件の記録（禁止事項2）を人が確認する経路として弱い。**

### 案C（推移的依存まで `pyproject.toml` に書く）

**`uv.lock` の役割と重複する。** 推移的依存はロックが完全に固定しており、`pyproject.toml` に書き写しても二重管理になり、必ず乖離する。

**`pyproject.toml` に書くのは「私たちが直接使うと決めたもの」に限る。**

### 案D（実験専用を分離しない）

**落選した候補が本番の依存に残る。** PoC が比較する4方式（W-1〜W-4）・ベクトル化の複数構成のうち、採用されるのは各1つである。分離しなければ、**採用しなかった手法のライブラリを本番環境がインストールし続ける。**

**分離しておけば、`dependencies` への移動が「採用した」という決定の記録になる。**

## 6. 運用

### 追加の手順

```bash
# 1. pyproject.toml を直接編集して `==` で追記する（uv add を使わない）
# 2. ロックを更新する
uv lock
# 3. 環境へ反映する（実験用グループを含める場合）
uv sync --frozen --group exp
```

**`uv lock` はロックの更新を明示的に行う操作であり、`uv add` と異なり `pyproject.toml` を書き換えない。** 宣言は人が書き、ロックはその宣言から導かれる。

### グループの区分

| 区分 | 置き場所 | 内容 |
|---|---|---|
| 本番依存 | `[project] dependencies` | **本番実装で使うことが確定したもの** |
| 実験依存 | `[dependency-groups] exp` | **PoC の比較候補、可視化、探索的分析にのみ使うもの** |
| 開発依存 | `[dependency-groups] dev` | テスト・リンタ等 |

**`exp` から `dependencies` への移動は、実験レポート（`report.md`）または ADR の決定を根拠とする。** 移動の理由を追跡できない形で移さない。

**判断に迷う場合は `exp` に置く。** 後から `dependencies` へ移すのは容易だが、逆は本番環境に不要な依存が残った状態を経ることになる。

### 記録

**実験の実行条件（`config.md`）には、使用したパッケージと版を引き続き記録する**（`.claude/rules/experiment-code.md` 禁止事項2）。**形態素解析辞書のように出力を変えるものは、必ず版を明記する。**

## 7. 想定される結果

| 良い影響 | 悪い影響・受け入れるコスト |
|---|---|
| `pyproject.toml` を読めば実際の版がわかる | 版の更新が手作業になる |
| 意図しない版の更新が起きない | 脆弱性修正の取り込みが自動で行われない |
| 辞書・モデルの版が実験条件として固定される | `uv add` より手数が1つ増える |
| 落選した候補のライブラリが本番依存に残らない | グループの指定漏れで実験が動かないことがある |

## 8. 見直す条件

1. **本実装フェーズに入り、依存の更新頻度が上がったとき。** セキュリティ更新の取り込みが手作業では追いつかない場合、`~=`（互換リリース）への緩和を検討する
2. **`exp` グループが空になったとき**（すべての候補の採否が確定したとき）。分離の必要性を再評価する
3. **`uv` が `pyproject.toml` を書き換えずに固定版を追加する手段を提供したとき**（`uv add --exact` 相当の挙動が本ADRの意図を満たす場合）。手順を簡略化できる
