# ADR-006: 参照論点リストは独立した公開ソースから作成し、`docs/` に置く

| 項目 | 内容 |
|---|---|
| ID | ADR-006 |
| 状態 | 採用 |
| 決定日 | 2026-08-19 |
| 関連 | [ADR-002](ADR-002-public-private-boundary.md)、要件定義書 5.2.1節・AR-008 |

## 1. 背景

クラスタ品質の評価およびベースラインとして、参照論点リストを2種類作成する（要件定義書 5.2.1節）。

| ID | 情報源 |
|---|---|
| 参照A | 施政方針演説・所信表明演説の項目 |
| 参照B | 提出議案リスト |

このうち**参照Aが問題となった。** 施政方針演説は本会議での発言であり、**国会会議録の内部に存在する。**
[ADR-002](ADR-002-public-private-boundary.md) は取得データを機密扱いとし、`docs/` に置けるものを集計軸と集計値に限っている。演説から抽出した論点名がこれに該当するかは、同ADRの区分表に定義がない。

当初、要件定義書 v0.7 の AR-008 で「論点名は集計値として記載可としてよいクラスタの特徴語と同種の抽象度にある」という**類推**により `docs/` 可と判断した。
しかしレビューにより、**この類推は機密境界を1セルの記述で拡張するものであり、ADRを起こすべき**と指摘された。

## 2. 決定

**参照論点リストは、国会会議録APIとは独立した公開ソースから作成する。** そのうえで `docs/inputs/` に置く。

| ID | 出典 | 会議録との関係 |
|---|---|---|
| 参照A | **首相官邸等が公表する演説の全文**（国会会議録APIを使わない） | 独立 |
| 参照B | 衆議院・参議院が公表する議案情報 | 独立 |

**参照Aの作成に国会会議録APIから取得したデータを使わない。** 同じ演説の内容が独立した公開ソースから入手できるため、そちらを出典とする。

記録する項目と制約は次のとおり。

| 項目 | 内容 |
|---|---|
| 記録する | 論点名（演説の項目見出しに相当する語句）、実施日、国会回次、出典URL |
| 記録しない | **演説本文。引用は行わない。** 見出しに相当する語句を超えて本文を転記しない |
| 保存先 | `docs/inputs/`（Git追跡・公開） |
| 改訂 | 追記のみ（`.claude/rules/documentation.md` 3.6節） |

## 3. 検討した選択肢

| 案 | 内容 | 採否 |
|---|---|---|
| A | 独立した公開ソースから作成し `docs/` に置く | **採用** |
| B | 会議録APIから抽出し、抽象度の類推により `docs/` に置く（v0.7 の処理） | 不採用 |
| C | 会議録APIから抽出し `private/` に置く | 不採用 |

## 4. 判断根拠

1. **境界問題そのものを消滅させる。** 案Bは「会議録由来のデータをどこまで `docs/` に書けるか」という解釈を必要とするが、案Aは**そもそも会議録由来ではない**ため、[ADR-002](ADR-002-public-private-boundary.md) の境界に触れない。解釈を増やさずに済む
2. **[ADR-002](ADR-002-public-private-boundary.md) の原則と衝突しない。** 同ADRは「出典が公開情報であることを理由に緩めない」「迷ったら `private/`」と定めている。案Bはまさにこの原則が禁じている形の論法だった
3. **評価の独立性が高まる。** 参照リストは評価対象データを評価するための基準である。基準の生成元が評価対象データの内部にあると、独立性への疑義が残る（前回レビュー I-006 の指摘）。案Aはこの疑義も同時に解消する
4. **実務上のコストが増えない。** 演説の全文は公表されており、会議録APIから取得するのと手間は変わらない

### 訂正（2026-08-19）: 判断根拠3は誤りである

> **決定（2章）は維持する。以下は根拠の一部を訂正するものであり、結論を変えない。**

上記の**判断根拠3「評価の独立性が高まる」は誤りである。** 訂正する。

根拠3は「配布元の独立」と「内容の独立」を同一視していた。**参照Aの入手経路を官邸の公表資料へ移しても、施政方針演説そのものは評価対象コーパス（対象期間の全発言）の内部に存在し続ける。** したがって「評価基準の生成元が評価対象データの外にある」とは言えず、評価上の独立性は生じない。

本ADRによって実際に解消されたのは**機密境界の問題のみ**である。

| 問題 | 状態 |
|---|---|
| `docs/` へ書くテキストが会議録由来であること（[ADR-002](ADR-002-public-private-boundary.md) の境界解釈） | **解消。** 入手経路が会議録の外へ移り、区分表を拡張せずに済んだ |
| 参照Aの内容が評価対象コーパス内に存在すること（評価の独立性） | **解消していない。** 残存する |

残存する論点の扱いは、要件定義書 5.2.1節および 7.1.1節に記載する。**参照Aとの一致率は「独立した基準に対する正解率」ではなく、「政策アジェンダとして設定された論点が発言群の中で分離可能な形で現れているか」を示す再現性の指標として解釈する。**

なお本ADRの7章に定めた一般則（参照データは評価対象データとは独立した公開ソースから作成する）を厳密に適用すると、**参照A自身がこれを完全には満たさない。** 一般則は「入手経路の独立」を求めるものとして読むこと。内容の独立まで求める参照データが必要になった場合は、会議録に含まれない情報源（報道、外部の政策分析等）を別途検討する。

## 5. 採用しなかった案を退けた理由

- **案B**: 判断根拠2のとおり、[ADR-002](ADR-002-public-private-boundary.md) が明示的に禁じている論法（公開情報だから緩める）に該当する。**類推による境界拡張は、前例として機能してしまう**ことが最大の問題である。今回は論点名という軽微な対象だが、同じ論法で「代表発言の要約なら可」「特徴的な一文なら可」と拡張されうる
- **案C**: 参照リストを `private/` に置くと、要件定義書や実験レポートから論点名を引用できなくなり、**評価結果を `docs/` に記述できない。** 過剰な制約であり、案Aで回避できる

## 6. 想定される結果

| 良い影響 | 悪い影響・受け入れるコスト |
|---|---|
| ADR-002 の境界を拡張せずに済む | 演説の公表ページを別途参照する手間が生じる |
| 参照リストの独立性が担保される | 会議録の記載と公表資料の記載に差異があった場合、どちらを採るかの判断が必要 |

最後の点について、**差異が生じた場合は公表資料を優先する。** 参照リストの目的は「公開情報を読めば分かる範囲」を定義することであり（要件定義書 7.1.1節）、会議録との一致は目的ではない。

## 7. 適用範囲と一般則

本ADRは参照論点リストに限らず、以下の一般則を定める。

**評価や比較に用いる参照データは、可能な限り評価対象データとは独立した公開ソースから作成する。**
**独立したソースが存在せず、会議録由来のデータから作成せざるを得ない場合は `private/` へ置く。** 抽象度の類推によって `docs/` へ置かない。

## 8. 見直す条件

- 独立した公開ソースが利用できなくなったとき（公表の停止、形式の変更等）。その場合は案Cへ移行し、参照リストを `private/` に置いた上で、`docs/` には一致率などの集計値のみを記載する
- [ADR-002](ADR-002-public-private-boundary.md) の機密境界そのものが見直されたとき
