# ADR-004: 規約の変更もブランチ経由とし、ADR-003 の例外規定を廃止する

| 項目 | 内容 |
|---|---|
| ID | ADR-004 |
| 状態 | 採用 |
| 決定日 | 2026-08-18 |
| 関連 | [ADR-003](ADR-003-branch-strategy.md)（本ADRにより例外規定を廃止）、`CLAUDE.md` 5章、`.claude/rules/documentation.md` |

## 1. 背景

[ADR-003](ADR-003-branch-strategy.md) の補足で、「規約自体の変更（`CLAUDE.md`・`.claude/rules/`・運用ADR）は `main` へ直接コミットしてよい」という例外を設けた。
理由は「規約は全ブランチへ即時適用されるべきであり、ブランチに閉じ込めると並行作業が古い規約のまま進む」というものだった。

しかし運用を開始した直後に、以下が明らかになった。

- **規約の変更は継続的に発生する。** 本プロジェクトでは規約を整備しながら開発を進めており、変更は一度きりではない
- そのため**例外が常態化し、`main` へ直接コミットする運用が恒久的に残る**。ADR-003 の「`main` へ直接コミットしない」という原則が実質的に無効になる

## 2. 決定

**規約の変更もブランチを経由する。`main` への直接コミットは行わない。ADR-003 の例外規定を廃止する。**

その上で、**規約変更をどのブランチに載せるかは影響範囲で判断する。**

| 影響範囲 | 載せるブランチ | 例 |
|---|---|---|
| **その作業に閉じる** — 特定の実験・開発の過程で判明した規約変更で、他の進行中の作業に影響しない | **その実験・開発のブランチに含めてよい。** 専用ブランチを切らない | 実験の中で出力形式の規約を補足する、特定フェーズの文書構成を調整する |
| **他の作業にも及ぶ** — 全体の運用方法が変わる、複数のブランチが従うべき規則が変わる | **規約配信用のブランチを切り**、`main` へ速やかにマージする | ブランチ運用の変更、機密境界の変更、ID体系の変更 |

規約変更は開発・実験の過程で継続的に発生する。**そのすべてに専用ブランチを要求すると運用が重くなり、逆にすべてを `main` へ直接コミットすると原則が形骸化する。** 影響範囲による使い分けが現実的な均衡点である。

判断に迷う場合は専用ブランチを切る。マージが早ければコストは小さい。

## 3. 検討した選択肢

| 案 | 内容 | 採否 |
|---|---|---|
| A | 例外を廃止し、規約変更もブランチ経由とする。載せるブランチは影響範囲で判断 | **採用** |
| B | ADR-003 の例外を維持する（規約変更は `main` へ直接コミット） | 不採用 |
| C | 例外を廃止し、規約変更には常に専用ブランチを要求する | 不採用 |

## 4. 判断根拠

1. **単独開発では、例外の前提が成立しない。** 並行して作業する他者が存在しないため、「他者の作業が古い規約のまま進む」という事象が起こらない
2. **例外の常態化を防ぐ。** 規約変更が継続的に発生する以上、例外を残せば `main` への直接コミットが恒久的に続き、原則が形骸化する
3. **ADR-003 の既存規定で問題は解決済みだった。** 同ADRはフェーズブランチについて「長命になるため `main` から乖離しないよう定期的に取り込むこと」と定めている。**この取り込みによって規約は速やかに伝播するため、例外規定はそもそも不要だった**
4. **規約変更は小さく、ブランチを短命にできる。** 切って直ちにマージすれば、`main` が古い状態にある時間はごくわずかで済む
5. **履歴の一貫性。** すべての変更が同じ形（ブランチ → `--no-ff` マージ）で記録され、「なぜこれだけ直コミットなのか」を後から検証する必要がなくなる

## 5. 採用しなかった案を退けた理由

- **案B**: 判断根拠2のとおり、例外が恒久化して原則が無効になる
- **案C**: 規約変更は開発・実験の過程で頻繁に発生するため、そのたびにブランチを切ってマージする手数が積み上がる。**実験の中で判明した小さな規約の補足まで専用ブランチを要求すると、規約を書くこと自体が億劫になり、暗黙のルールが増える**という逆効果を招く

## 6. 想定される結果

| 良い影響 | 悪い影響・受け入れるコスト |
|---|---|
| すべての変更が同一の形で履歴に残る | 規約変更のたびにブランチ操作が必要になる |
| `main` への直接コミット禁止が原則として維持される | 長命ブランチでは、規約が届くまで `main` の取り込みを要する |

2つ目のコストは、ADR-003 が定める「長命ブランチへの `main` 定期取り込み」で対処する。
規約の内容自体は、ファイルがどのブランチにあるかに関わらず、決定した時点から適用する。**ファイルの所在と規約の効力を混同しない。**

## 7. 見直す条件

- **複数人での並行開発になり、規約変更のマージ待ちが実際に問題化したとき。** その場合も直コミットの復活ではなく、規約変更ブランチを優先的にマージする運用を先に検討する

## 9. 発効前の履歴について

本ADR以前に、規約変更として `main` へ直接コミットしたものが2件ある（`440ce53`、`dc03d69`）。
